# Changelog

Notable changes per release, newest first. Format loosely follows [Keep a Changelog](https://keepachangelog.com/); versions are the desktop / web app versions (tags `vX.Y.Z`, with `X.Y.0` tagged `vX.Y`). Each release's frozen web app is at `https://regionstockholm.github.io/intehrgrator/<tag>/`.

Add an entry under **Unreleased** in every feature or fix PR that changes user-visible behaviour; `deno task release` and Actions **Release create** move it into the version they tag.

## [Unreleased]

- **Hint actions on the canvas** ([#353](https://github.com/regionstockholm/intehrgrator/pull/353)): applying a constant (including units), decision table, or sheet lookup initializes and renders its connected Blockly blocks. Each action undoes and redoes the canvas, grid, and hint settings together. The tutorials show the Hints flow and connected grid scaffold.

- **Value-set hints** ([#353](https://github.com/regionstockholm/intehrgrator/pull/353), [#322](https://github.com/regionstockholm/intehrgrator/issues/322)): a coded, ordinal, string-list, or multi-unit slot stays empty. A 💡 badge and the Hints tab (next to Mapping Spec and Tables & Sheets) list the allowed values. `assumed_value` is only a star. Use as constant, a decision table, or a sheet lookup turns the hint into a mapping; the source column starts blank, and the interactive Contribution Builder can insert a prompt that asks the AI to fill it. Dismissed hints are remembered until the allowed codes change. Hints are not mapped and are not emitted, so an unmapped Position no longer becomes Standing. Headless and MCP use the same actions through `apply_hint` and `list_slots`.

- **Optional DATA_VALUE fields** ([#351](https://github.com/regionstockholm/intehrgrator/pull/351), [#350](https://github.com/regionstockholm/intehrgrator/issues/350)): the cogwheel on text, coded text, quantity, count, proportion, ordinal, scale, duration, date, date-time, time, multimedia, and interval shells offers the reference-model attributes that were missing (`mappings`, `hyperlink`, `normal_range`, `other_reference_ranges`, temporal `accuracy`, multimedia `data` / `integrity_check` / `thumbnail` / `uri`, interval `lower` / `upper`). New blocks: Term mapping (`match`, `target`, optional `purpose`) and Reference range (`meaning`, `range`). Paragraph `items` and time-specification `value` show on those shells. Mapping preview and every conversion script (TypeScript, Java, XQuery, Go template) emit the mouths you add. A quantity with no magnitude is left out, even if a range is filled. Multimedia bytes are a base64 text block (or a list of numbers).

- **ehrtslib 0.12.0** ([release](https://github.com/ErikSundvall/ehrtslib/releases/tag/v0.12)). Contribution Builder records provisional→stored versioned-object uuid pairs when a CDR replaces the client uid, and can continue a committed draft from the stored version ([ehrtslib#176](https://github.com/ErikSundvall/ehrtslib/issues/176), [#177](https://github.com/ErikSundvall/ehrtslib/issues/177)). `webTemplateToOpt` keeps node ids and ACTION `ism_transition` mins through OPT ↔ Web Template round trips ([ehrtslib#271](https://github.com/ErikSundvall/ehrtslib/issues/271)).
- **Release from Actions** ([#348](https://github.com/regionstockholm/intehrgrator/pull/348), [#220](https://github.com/regionstockholm/intehrgrator/issues/220)): **Release create** takes a semver and pushes an annotated tag after bumping version files on the chosen branch (default `main`). The existing tag workflow still publishes frozen Pages, desktop binaries, and the VSIX. `deno task release` no longer needs the GitHub CLI.

- **VS Code file projects** ([#305](https://github.com/regionstockholm/intehrgrator/pull/305)): create, edit and reopen mappings backed by workspace files, with native save/undo and unsaved-document recovery. Per-file language settings and local multi-file targets survive reopening. Saving refreshes generated code, mapping-preview results and diagnostics; `project:run --check` verifies the committed artifacts in CI. File projects are an extra option: the web app, desktop app and headless runner, and the Project Bundle / `.intehrgrator` format, are unchanged. In VS Code there is one undo history (VS Code's), no autosave, and opening a project never rewrites its output; generated files stay inside the project folder (not in `.git` or other dot-folders, not through outward symlinks). Without a Source Schema, source languages are saved as `source.languageSettings`. Each GitHub Release uploads `intEHRgrator.vsix` next to the desktop binaries (`deno task extension:package` / `release.yml`). **VS Code migration:** the extension's earlier standalone workbench (development builds only; no VSIX was published), which kept projects in VS Code's extension storage, is replaced by file projects, and projects saved there are no longer listed. To keep one, export it as `.intehrgrator` with the earlier build before upgrading, then open it in the web or desktop app or create a file project with the same target, Source Schema and examples ([VS Code file projects](docs/VS_CODE.md)).

## [0.14.0] - 2026-11-04

A target can start from a minimal JSON, XML, or text example, Handlebars gains `inc` and `dec`, and Java conversion scripts follow TypeScript on lists, identifiers, counts, and coded text. Sheets and decision tables use the pane width, and the obstetric fixtures add OPT2, Web Templates, and canonical JSON beside Simplified FLAT.

- **Schema-less target** ([#345](https://github.com/regionstockholm/intehrgrator/pull/345), [#198](https://github.com/regionstockholm/intehrgrator/issues/198)): Load target & default context map can start from a minimal JSON, XML, or text example. A conversion start sits above that document, and the default context map you picked still applies.
- **Java conversion scripts** ([#345](https://github.com/regionstockholm/intehrgrator/pull/345), [#333](https://github.com/regionstockholm/intehrgrator/issues/333)): generic lists use the reference-model element type, identifiers call `setId`, counts use `long`, and nodes that are not LOCATABLE omit the archetype node id. Coded text follows the template value set, and a quantity with units but no magnitude is left out, as in TypeScript.
- **Desktop dev window** ([#345](https://github.com/regionstockholm/intehrgrator/pull/345), [#334](https://github.com/regionstockholm/intehrgrator/issues/334)): `deno task desktop` includes the workbench files, so the Linux window can start, and flags after `--` (`--headless`, `--load`, `--language-plugin`, and the rest) reach the app.
- **Attach original target format too** ([#344](https://github.com/regionstockholm/intehrgrator/pull/344), [#290](https://github.com/regionstockholm/intehrgrator/issues/290)): the AI menu and the chat copy menu use that label in English, Swedish, German, Spanish, Catalan, and French.
- **Sheets and decision tables use the pane** ([#344](https://github.com/regionstockholm/intehrgrator/pull/344), [#290](https://github.com/regionstockholm/intehrgrator/issues/290)): columns follow their text and fill leftover width, and the sheet tabs use the full toolbar and scroll when the names do not fit.
- **Context map stays off the target tree** ([#344](https://github.com/regionstockholm/intehrgrator/pull/344), [#290](https://github.com/regionstockholm/intehrgrator/issues/290)): after the canvas is measured, the product tree moves clear of the default context map instead of being drawn on top of it.
- **Obstetric template formats** ([#343](https://github.com/regionstockholm/intehrgrator/pull/343)): each operational template under the obstetric generic-entry fixtures is also stored as OPT2 and as a Web Template. MHV1 and partogram examples are Simplified FLAT (`*.flat.json`) and Canonical JSON (`*.canonical.json`) in the same folders. Each example set uses one of those formats. The mapped MHV1 sets stay on Simplified FLAT and the prenatal-visit Web Template.
- **Handlebars `inc` and `dec`** ([#342](https://github.com/regionstockholm/intehrgrator/pull/342), [#339](https://github.com/regionstockholm/intehrgrator/issues/339)): `{{inc n}}` is one more than `n` and `{{dec n}}` is one less, as in Kintegrate (`{{inc @index}}` is a 1-based row number inside `#each`). Mapping preview and TypeScript, Java, XQuery, and Go Template output use the same helpers.
- **GitHub Pages startup**: the web app asks for desktop language plugins only in the desktop app, so the browser no longer logs a 404 for `/api/v1/language-plugins` on the static site.
- **Example set load**: conversion tests wait until the set has finished loading, and the conversion script is generated once.
- **Obstetric partogram generic entry**: four FLAT partographs (a primip left of the alert line, a fast multip, a primip who crosses the alert line and is augmented, and thick meconium with a low scalp pH) load against `generic-obstetrix-partogram-v1`. The target is the resolved Partogram.v1 Web Template. There is no mapping yet.

## [0.13.0] - 2026-11-03

Conversion scripts share imported helpers, openEHR templates can be source or Web Template target, **Include when** and named loop items tighten mappings, and the Obstetric MHV1 example maps generic-entry FLAT onto a prenatal Web Template.

- **Shorter conversion scripts** ([#332](https://github.com/regionstockholm/intehrgrator/pull/332), [#242](https://github.com/regionstockholm/intehrgrator/issues/242)): TypeScript, Java, and XQuery import shared helper modules (only the helpers that mapping uses) instead of pasting them into every script. Import paths in Generated conversion script(s) open the helper or library source. The desktop app can lazy-load another conversion script language from a manifest URL in a Deno worker sandbox (`--language-plugin`).
- **openEHR template as source or target**: an operational template (`.opt`, `.opt2`, `.oet`) loads as a source schema for an integration-archetype to CKM conversion. Its source tree is that template's Web Template. A `.wt.json` target stores the Web Template document, so the composition root can serialize Canonical JSON, Canonical XML, Simplified FLAT, or Simplified STRUCTURED, the same choices as an OPT target. FLAT and STRUCTURED need that document.
- **Quoted flat source keys**: a TypeScript Conversion Script reads `$["composer|name"]` as that key. The quote characters used to become part of the lookup. An authoring index `[0]` is the first element, as in Mapping preview.
- **A cluster can sit in other_context**: an item-structure socket accepts a CLUSTER, which is how templates constrain `other_context` and protocol, so that cluster saves and loads and stays a CLUSTER.
- **Obstetric MHV1 generic entry**: the integration OPT is the source schema and four FLAT compositions are the examples. They map onto the prenatal-visit Web Template. Include when emits weight, last menstrual period, EDD, the snus summary, and the assessment only when that source value is present. Category, setting, composer, care unit, and the dates are source paths. The example set is saved as Simplified FLAT; the composition root still offers the other encodings. Height, tobacco, alcohol, and occupation stay unmapped: this Web Template has no trustworthy name for those slots. `BerakForSM`, `BerakForUL`, and `BerakForET` are different delivery-date calculations (SM is senaste mens, UL is ultraljud); EDD stays `berakforsm`. `bp_comp` is a separate date-time (Swedish obstetrics “bp” can mean beräknad partum) and is empty in these examples. Blood pressure is `Blodtryck` on the partogram template, which has no instances. Guessed slots carry a confidence percent and a comment; the open choices are questions with options in the suggestions file.
- **Lung MDT and chemotherapy keywords use Include when**: an optional TakeCare keyword is omitted with **Include when** instead of a statement if. A Lung MDT Note that is only `{{path}}` is a source path. A guard that was `(eq path "MR")`, `(and …)`, or `(or path path …)` is a compare, an and, or an any-of list, not a Handlebars string stored on a source block. Decision-table presence inputs (`has_intention`, and the same shape) are boolean source paths: a missing path is false, so they are not wrapped in a true/false if. A TypeScript Conversion Script walks JSON source paths the same way Mapping preview does, so a missing index is empty and a path that lands on a list is that list.
- **Named loop items** ([#328](https://github.com/regionstockholm/intehrgrator/pull/328)): inside a nested **for each**, a source path can read an outer item by name (`dag.StartTid`). The planned administration date on Karda ordination no longer uses `$.KurDagar[1]`.
- **Include when** ([#328](https://github.com/regionstockholm/intehrgrator/pull/328)): a wrapper in Loops & Logic emits an optional openEHR container only when a boolean condition is true, so a measurement without a pulse does not keep a time-only EVENT.

## [0.12.0] - 2026-11-02

Preview and TypeScript output now agree on every mapped example set, the MCP tools are fixed after two AI-agent retests, and ehrtslib is 0.11.0.

- **Example sets follow the repo**: the Agent API and unit tests load `examples/example-sets.json` from the source tree, so a leftover `src/desktop/www/` or `dist/` from an earlier build cannot hide newer gold mappings.

- **ehrtslib 0.11.0** ([release](https://github.com/ErikSundvall/ehrtslib/releases/tag/v0.11), up from 0.7 via 0.8, 0.9 and 0.10). Simplified FLAT and STRUCTURED use the output flavour, as Better and EHRbase return it: every value at its own path, no `ctx/` keys, no `data` step for HISTORY, and RM attributes without a template path as `_<attr>` (for example `context/_health_care_facility`). A coded text on a `DV_TEXT` node is read, an ELEMENT with no value constraint is written as `<type>_value`, and name-constrained siblings (two `SECTION.adhoc` headings, Karda's *Organisationsnummer* next to *Identifierare*) stay apart, so Simple-vitals-series, OBX and Karda validate in both encodings ([ehrtslib#250](https://github.com/ErikSundvall/ehrtslib/issues/250), [#255](https://github.com/ErikSundvall/ehrtslib/issues/255), [#256](https://github.com/ErikSundvall/ehrtslib/issues/256)). Output validation is stricter: unknown or ineffective FLAT keys, missing RM-mandatory attributes and coded text without an exact match in the template's list are errors ([ehrtslib#216–#219](https://github.com/ErikSundvall/ehrtslib/issues/216), [#231](https://github.com/ErikSundvall/ehrtslib/issues/231), [#235](https://github.com/ErikSundvall/ehrtslib/issues/235)). Visible changes: renamed siblings use the spec slot id with a space, `[openEHR-EHR-SECTION.adhoc.v1, 'Calculated scales']`, and a repeating ELEMENT keeps its own max, so the first of a 0..* identifier is `identifierare:0` ([ehrtslib#268](https://github.com/ErikSundvall/ehrtslib/issues/268)).
- **History the agent can read** ([#316](https://github.com/regionstockholm/intehrgrator/issues/316)): `get_history` no longer returns a Project Bundle before and after every change. The default is the timeline (who, what, which slots). `includeBundles` or `seq` fetches bundles; `sinceSeq` and `limit` page. The history panel is unchanged.
- **Agent changes stay the agent's** ([#317](https://github.com/regionstockholm/intehrgrator/issues/317)): a load or other awaited change is attributed to the agent that started it. A request from the desktop window, which has no agent id, no longer rewrites that entry as "You".
- **History lines say what changed** ([#318](https://github.com/regionstockholm/intehrgrator/issues/318)): `map_slot` with a constant is a `map_slot` entry ("Set … = …"), not "Import AI suggestions". Slot paths in summaries use the same id as `list_slots`, without a doubled slash.
- **Preview and TypeScript validate the same output** ([#319](https://github.com/regionstockholm/intehrgrator/issues/319)): with Simplified FLAT, Mapping preview validates the FLAT document it shows, as TypeScript mode already did, so both modes give the same verdict for the same document. With ehrtslib v0.9 the FLAT round trip keeps RM-mandatory fields, and the Simple-vitals FLAT output is valid in both modes.
- **MCP output** ([#320](https://github.com/regionstockholm/intehrgrator/issues/320)): TypeScript output no longer fills an unmapped coded element with the value set's first choice (Position "Standing" on an otherwise empty observation). `generate_script` with `path` returns language, path and size, not the script. `list_slots` lists openEHR terminology codes for slots such as setting (225 home, 227 emergency care, …). An unmatched coded value such as "flying" is the same shape in both modes, with the message `value 'flying' is not in the value set: …`. After an unmapped load, `mappedSlots` is 0; the composition category term pick counts as `defaultedSlots`. MCP `initialize` says when the version-pinned docs are the last release and the default-branch copies match this build.
- **Karda preview keeps every substance** ([#321](https://github.com/regionstockholm/intehrgrator/issues/321)): a loop inside another loop runs once per outer item in Mapping preview, as in the generated script, so a treatment day with two or three substances shows all of them. Preview also writes DV_QUANTITY units mapped on the canvas (Karda doses in mg).
- **Coded values in TypeScript output**: a coded record from an if/else or Decision table (Karda diagnosis code) is no longer written as "[object Object]", and ISM states and composition category get their openEHR code in both modes.
- **OBX mapped set validates in TypeScript mode**: output with a DV_IDENTIFIER type no longer stops validation with "obj._type?.includes is not a function". With ehrtslib v0.10 the interval check is on again ([ehrtslib#247](https://github.com/ErikSundvall/ehrtslib/issues/247)).
- **Missing source values in TypeScript output**: an optional element whose source value is missing (a measurement without body position, an order without trial id, a missing count) is left out, as in Mapping preview, instead of an empty element, an empty text or a crash on NaN. Item structures that end up empty are left out too.
- **Preview after reload**: a DV_TEXT slot mapped as coded text stays DV_CODED_TEXT in Mapping preview after the project is saved and loaded again.
- **if/else on a source value**: a text or number condition (for example "if there is a trial id") becomes an *is not empty* test on the canvas. TypeScript output compiled it to `false` before.
- **True/false values**: a mapped DV_BOOLEAN is a boolean in TypeScript output (it was a string and dropped from FLAT output); "false" reads as false in both modes.
- **Composer and facility from the source**: a `map(name, id, …)` on `composer` or `health_care_facility` replaces the Default point on the canvas, so it is saved, used by TypeScript output and kept when the instance encoding changes.
- **Nested organisation clusters**: an archetype nested in itself (Karda *Vårdgivare* inside *Vårdenhet*) is written with its archetype id, so it reaches FLAT output. Preview adds a mapped DV_IDENTIFIER type, issuer and assigner to the id, as TypeScript does.
- **Nested loops with a relative path**: a loop inside a loop may use a LIST path relative to the outer item (`Substanser` in the treatment-day loop), so each day gets its own substances.
- **Activities in canonical output**: every ACTIVITY has its RM-mandatory `action_archetype_id` (`/.*/`, as ehrtslib's FLAT reader fills it), so Karda's ordination set validates as canonical JSON too.
- **STRUCTURED output is validated**: with Simplified STRUCTURED as Instance encoding, output validation reads the document back through ehrtslib and checks it against the template, as for FLAT. It reported "Cannot determine type for object" before.
- **Nested loops in XQuery**: a relative LIST path inside another loop reads the outer item in XQuery output as well, instead of stopping with `DYNAMIC-LOOP-PATH`.
- **Renamed template nodes keep their names on the canvas**: when a template renames an archetype node (two `SECTION.adhoc` headings named *Vital signs* and *Calculated scales*), blocks and slot lists show the template's name in its primary language, as EHRbase and ehrtslib Web Templates do, instead of the archetype's term text. Other display languages show the archetype's translation. Output names were already right.
- **Karda ordination mapping rerun on ehrtslib v0.10**: substances loop per treatment day with the relative path `Substanser`, course number and trial id map directly, and the trial name comes from the template. Output is unchanged.
- **Canonical openEHR output in both modes** ([#309](https://github.com/regionstockholm/intehrgrator/issues/309), [#310](https://github.com/regionstockholm/intehrgrator/issues/310)): Mapping preview and TypeScript output now give the same canonical openEHR JSON for the Simple-vitals sets. Free text mapped to a coded slot gets its code and the template rubric in TypeScript output too. Preview writes `CODE_PHRASE` as `terminology_id` + `code_string`, puts no `name` on `EVENT_CONTEXT`, and adds `subject` (PARTY_SELF) to entries. TypeScript output uses `IANA_character-sets` for `encoding`, writes party Default points with `_type`, always names `HISTORY`, and leaves out a quantity with units but no magnitude. The Simple-vitals gold mappings now set `composer` and `setting`.
- **MCP tools** ([#311](https://github.com/regionstockholm/intehrgrator/issues/311), [#312](https://github.com/regionstockholm/intehrgrator/issues/312), [#313](https://github.com/regionstockholm/intehrgrator/issues/313)): `load_example_set` and `list_function_library` with `catalogUrl` work again. New `list_example_sets`; without a catalog, the bundled one is used. `map_slot` takes a constant `value` (on a coded slot, such as `setting`, a code or text from its values, or `"openehr::238|other care|"`, writes code and text) and warns about coded slots. `import_suggestions` no longer reports a missing `target` when it is left out. `run_test` returns `valid`, `get_snapshot` splits `mappedSlots` and `defaultedSlots`, root slot ids read `/context/…`, `export_bundle` with `path` returns a short result, and `INTEHR_AGENT_ID` / `INTEHR_AGENT_NAME` keep one agent identity.
- **Linux desktop** ([#314](https://github.com/regionstockholm/intehrgrator/issues/314)): README and release notes say the AppImage needs the system WebKitGTK 4.1 (`libwebkit2gtk-4.1-0` on Debian/Ubuntu, `webkit2gtk4.1` on Fedora).

## [0.11.0] - 2026-10-29

Minor release: a `DV_TEXT` slot can be mapped as coded text, multilingual OPT files keep labels and Web Template ids per language, and parallel IDE agents lease slots so they do not overwrite each other. AI chat asks before it drops mapping context, and the openEHR validator is ehrtslib v0.7. Handlebars is 4.7.10 and fast-xml-parser is 5.11.2.

- **Security**: Handlebars is 4.7.10 and fast-xml-parser is 5.11.2 ([#302](https://github.com/regionstockholm/intehrgrator/pull/302)). Handlebars 4.7.10 closes [GHSA-8r5x-fm3f-whwj](https://github.com/advisories/GHSA-8r5x-fm3f-whwj), [GHSA-p8wg-vrv2-v86f](https://github.com/advisories/GHSA-p8wg-vrv2-v86f) and [GHSA-xw65-4hp5-5hc7](https://github.com/advisories/GHSA-xw65-4hp5-5hc7). fast-xml-parser 5.11.2 closes [GHSA-gh4j-gqv2-49f6](https://github.com/advisories/GHSA-gh4j-gqv2-49f6).
- **Coded text on DV_TEXT slots** ([#274](https://github.com/regionstockholm/intehrgrator/issues/274)): every `DV_TEXT` slot can now be mapped as its subclass `DV_CODED_TEXT` (value + code + terminology), as openEHR allows. A template cannot forbid this. Right-click a text block on the canvas and choose **Use coded text (DV_CODED_TEXT)** to get code and terminology sockets, or **Use plain text (DV_TEXT)** to go back. Each switch is one undo step. When the source has a code and its code system for a text (e.g. a diagnosis with an ICD-10 code), the AI now maps it as coded text instead of dropping the code. It still offers text only or a TERM_MAPPING as alternatives. The slot tree shows `DV_CODED_TEXT` for such a slot. Canonical JSON/XML, Simplified FLAT (`|code`, `|terminology`), TypeScript, XQuery and Java output carry the code. Fix: a coded text whose code comes from a Decision table (e.g. *Position* in Simple vitals) now keeps its code in XQuery and Java output (it was empty).
- **AI chat: no mapping context dropped without asking** ([#292](https://github.com/regionstockholm/intehrgrator/issues/292)): when the history is above the limit for the model, Send now stops with a card (**Continue with trimmed history**, **Start new chat with summary**, **Cancel**) instead of dropping old turns on its own. The 400k-character localStorage cap now only cuts the stored copy (the open chat keeps everything) and says so once. The agent no longer stubs out an older `get_example` / `list_slots` / … result when the newer call had other arguments; `get_source_tree` goes 64 levels deep (was 8) and marks cut nodes with `childrenOmitted`; the copy prompt counts the constraint warnings, sheet rows and JSON Schema `examples` it leaves out.
- **Fix: output names no longer follow the UI language**: since multilingual OPT files (#279), a node's RM `name/value` was its label in the language shown. So with an English UI, the Karda sets wrote English names, and the Swedish name constraints rejected them (Karda unmapped sets: 76 validation messages in English, 24 in Swedish). A node you have not renamed now gets the template's name constraint when there is one. Otherwise it gets the term in the template's primary language (lang.1, which for OPT 1.4 is the top-level `<language>` chosen at export). A name you typed yourself is kept. The Karda unmapped sets now give the same 12 messages in any UI language (only the pre-existing missing `description`).
- **ehrtslib v0.6** ([release](https://github.com/ErikSundvall/ehrtslib/releases/tag/v0.6)): validation messages give RM paths as `/content[0]/data/…` (was `/content/[0]/data/…`). A target ADL with a fatal cADL error now fails to load with the parser's message (line, column, token) instead of loading a partial archetype. Templates loaded from GitHub (`.t.json` + archetypes) take their per-template terms from ehrtslib instead of a local rebuild from the Web Template, and GitHub OPTs also take Simplified FLAT ids from the original language. Mapped Karda outputs now report an empty `ism_transition/careflow_step` value. Sibling matching by node id is in ehrtslib; the earlier name-based sibling patch is dropped (it caused false `name/value` errors on Karda). The local validator patch is gone as of ehrtslib v0.7.
- **ehrtslib v0.7** ([release](https://github.com/ErikSundvall/ehrtslib/releases/tag/v0.7)): the openEHR output validator is now ehrtslib's own, unpatched. It no longer checks inside an optional attribute the output leaves out, such as `protocol` or `state` ([ErikSundvall/ehrtslib#198](https://github.com/ErikSundvall/ehrtslib/issues/198)), and no longer asks for `EVENT.offset`, which is derived ([#200](https://github.com/ErikSundvall/ehrtslib/issues/200)). The local validator patch (`scripts/patch-ehrtslib-validator.ts` and the `vendor/ehrtslib-overrides/` file it wrote) is gone, so `deno task vendor` only clones the example archetypes. UCUM unit checks are back on ([#199](https://github.com/ErikSundvall/ehrtslib/issues/199)). Units such as `/min`, `1/min` and `{beats}/min` pass, and an output with a unit that is not UCUM now gets a validation message. Validation messages for the bundled Example Sets are unchanged.
- **AI chat: prompt caching for Claude via OpenRouter** ([#277](https://github.com/regionstockholm/intehrgrator/issues/277) §6): requests to an `anthropic/…` model on OpenRouter now ask for Anthropic's automatic prompt caching (`cache_control`), so each tool step and each new turn reads the earlier part of the chat from the cache (about a tenth of the input price; the first write costs 1.25×). OpenAI, Gemini, DeepSeek and Grok cache by themselves; Anthropic's own OpenAI-compatible endpoint does not support caching, so its requests are unchanged.
- **Id language per target file** ([#289](https://github.com/regionstockholm/intehrgrator/issues/289)): an **Ids** dropdown on the target's COMPOSITION root block picks the language of that target's Web Template ids, and so of its Simplified FLAT paths. It lists the file's languages as ISO codes with their names, the template's primary language (lang.1) first and default. For an OPT 1.4 file the primary language is its top-level `<language>`, chosen at export (e.g. `sv` for `…MedKurdag….sv.en.opt`, whose archetypes are English originals); ehrtslib calls it `original_language`. Only ids change: labels, mappings (slot ids are archetype paths) and output names stay. Once source mappings exist, the app asks before it changes the FLAT paths; Undo reverts the choice. A Web Template JSON file keeps its own ids. The project now stores each file's language settings with that file: `target.languageSettings` = `{languages, idLanguage, labelLanguage}` (languages in order, lang.1 first; `idLanguage` is `"primary"` or an ISO code; `labelLanguage` is the 💬 choice) and `sourceSchema.languageSettings` = `{languages, labelLanguage}`, restored on reload.
- **Source descriptions say their language** ([#277](https://github.com/regionstockholm/intehrgrator/issues/277) §5): `get_source_tree` now gives `descriptionLanguage` (the source's first language when the schema has texts in it), `sourceLanguages` and `schemaLanguages`, and marks a node with `lang` only when its description had to fall back to another language (e.g. an element documented only in English in a Swedish-first XSD). `get_source_tree {language: "en"}` (HTTP `?language=en`) returns the descriptions in another of the schema's languages without changing the source pane. The AI chat's source outline says which language its descriptions are in and marks the others, e.g. `/Visit/Weight decimal [1] — (en) Body weight in kg.`
- **Multilingual OPT files** ([#279](https://github.com/regionstockholm/intehrgrator/issues/279), [#277](https://github.com/regionstockholm/intehrgrator/issues/277)): an OPT 1.4 XML file with translations (per-archetype term definitions, e.g. `simple-diagnose-and-vitals.opt` in English, Swedish and German) now lists all its languages, so the 💬 button, `target.lang.N` and the AI `labels` work for it as for Web Templates. Before, such a file offered only its original language. The AI slot tree's descriptions, value descriptions and `get_slot`'s labels per language come from the translations too. Simplified FLAT ids come from the original language by default, whatever 💬 shows; the Ids dropdown ([#289](https://github.com/regionstockholm/intehrgrator/issues/289)) picks another language for that file. ehrtslib reads every OPT 1.4 language and builds one Web Template with all of them ([ErikSundvall/ehrtslib#160](https://github.com/ErikSundvall/ehrtslib/pull/160)). In the 💬 list, a code that is not ISO 639-1 is shown as written with ⚠ and a tooltip.
- **Labels in the source's language; 💬 language widgets** ([#279](https://github.com/regionstockholm/intehrgrator/issues/279), [#277](https://github.com/regionstockholm/intehrgrator/issues/277) part 4): the source's languages (`xml:lang`, JSON `x-lang` / `x-i18n`, or set under **AI ▾ → Languages…**) put the target's languages in order: matches first, then (only if none matched) the UI language, then the language the template was written in. The target pane shows its labels in the first of these by default, so a Swedish source gets the Swedish labels of a multilingual template. The **Model** language menu is replaced by a 💬 button in the target pane (keyboard: arrows, Enter, Esc) to pick another language, kept with the project until you choose **Follow the source**; hovering a target row shows its label in the other languages. A bilingual XSD or JSON Schema source gets its own 💬 for the language of its descriptions. The AI always gets the labels and descriptions in that first language, whatever the panes show, so switching the shown language does not change the prompt; other languages the source uses are added per slot as `labels` (Languages… → all, or the first only). Older projects keep the target language they were shown in. The AI chat's source outline now ends each node with its description (first sentence, in the source's first language).
- **AI sees what each slot means** ([#277](https://github.com/regionstockholm/intehrgrator/issues/277), part 3): slot-tree rows now carry the target's own description (first sentence), comment, annotations, term bindings, ordinals, numeric range and precision, pattern, length, format, examples, default, and a description per allowed value — from the OPT (via its Web Template), JSON Schema (`description`, `$comment`, `enum` + `x-enumDescriptions`, `x-i18n`, `minimum` …) or XSD (`xs:documentation`, facets, enumeration docs). An archetype's or object's description is given once on its group. `get_slot` returns the full texts and all languages. **XSD targets** are now read with the same XSD reader as XSD sources (#278): elements of named complex types, `ref`, groups, attribute groups and extensions now become slots (before, e.g. `Diagnosis` of type `DiagnosisType` was one value slot without its `Code` and `@primary`).
- **AI prompts: stable guide first, models named once, raw target only on request** ([#277](https://github.com/regionstockholm/intehrgrator/issues/277), part 2): copy & paste prompts now start with a fixed guide (response format, references, slot tree format, block examples, rules) that is the same for every project, so chat providers can cache it; the project part follows under `# Project`. AI chat sends that guide in the system message. A new **Models** section names the template with each archetype id and version (or the XSD namespace and root element, or the JSON Schema `$id`), for target and source, copied from the files. The raw target file is no longer attached to copy & paste prompts: tick **Attach original target** in the AI menu (or the chat's copy menu) to include it; the choice is saved with the project. SDV copy prompt (embed files): about 81,000 → 7,400 tokens. Format and workflow links now point at this release's own docs (`…/intehrgrator/v0.11/docs/…`). MCP `initialize` returns `instructions` with the workflow in short.
- **Compact slot tree for the AI; new `get_slot` tool** ([#277](https://github.com/regionstockholm/intehrgrator/issues/277), part 1): the AI chat, the copy & paste prompt and MCP / Agent API `list_slots` now describe the target as a slot tree, one group per repeating container or archetype node, with short slot ids (`group` + row `id`), fixed units/codes and allowed values once per slot. The old slot manifest and the separate repeatable-container list are gone; the SDV `api` prompt drops from about 6,200 to 3,700 tokens and MHV1 from 13,700 to 9,700. Every id form still works in `map_slot`, `import_suggestions`, `lease_slot` and `release_slot` (full skeleton id, compact id, unique tail). **MCP output change:** `list_slots` returns `{revision, groups}`; pass `view: "rows"` (HTTP `?view=rows`) for the earlier flat rows. `get_slot {id}` (HTTP `GET /slot?id=`) returns one slot in full, with documentation, every value set entry and the constraint from the target file. Measure with `deno task measure:context`.
- **XSD as Source Schema; XML sources over MCP** ([#278](https://github.com/regionstockholm/intehrgrator/issues/278)): an `.xsd` loaded as Source Schema is now read as a schema — element and `@attribute` paths, types, multiplicity and `xs:documentation` — instead of as an XML document whose tree showed `/xs:schema/xs:element/…`. In the headless app (MCP stdio, scripts) XML and XSD sources failed with `DOMParser is not defined` while the tool reported success; they now load, and a file that cannot be read is a tool error. `get_source_tree` also returns each node's `description`.
- **Warning before you edit inside an agent's lease** (S-15, ADR 0014): a change to something an MCP agent leases is held, and a dialog names the agent with a live countdown to the end of the lease. **Edit anyway** saves it and stops asking about that lease; **Cancel** takes it back; when the lease ends the dialog closes and the change is saved. You still win: the agent's next write to a slot you changed in its lease is refused once (409 `humanWins`, MCP `isError`), and the status line says so. Asked once per change you make (end of a drag, field edit or click), never per keystroke.
- **Tutorial: parallel IDE agents** ([docs/tutorial/parallel-agents.md](docs/tutorial/parallel-agents.md)): two or three IDE agents on one canvas, leases on slots and subtrees, what a refused write looks like, and the lease markers. `scripts/parallel_agents_demo.ts` plays three agents against a running app.
- **AI chat: live token use, context ring and an optional token budget** ([#276](https://github.com/regionstockholm/intehrgrator/issues/276)): a meter next to **Stop** shows the tokens the chat has used, updated after every step from the provider's reported usage (input, cached input, output, cost when given; `~` marks an estimate when the provider reports none). A ring shows how full the model's context window is (known for common models; set it for others in the meter's popover). An optional token budget per chat warns at 80 % and pauses at 100 %; **Raise budget … and continue** lets the model go on. The step limit went from 16 to 100 and is now only a guard against a model that loops, so ordinary mapping no longer stops for "continue". Old turns are dropped relative to the model's context window (half of it, at least 64k tokens) instead of always at 64k. Streaming requests ask for `stream_options.include_usage`; a provider that rejects it is asked again without.
- **Who leases what, on the canvas**: a block an MCP agent leases gets a dashed frame in the agent's colour and a 🔒 tag with its name (a thicker frame and **subtree** for a subtree lease). The Mapping Editors header shows a chip per agent with its number of leases; click it to jump to the next leased block. History shows the agent's name next to its IDE (**MCP Bo · cursor**), so two chats from one IDE can be told apart. Calling `register_agent` after an agent's first change renames that agent instead of creating a second one.
- **Leases for parallel MCP agents** (S-15): `lease_slot` takes `subtree: true` to lease a node path and every slot below it, such as `…//context/EVENT_CONTEXT`. A lease now holds for *every* change by another MCP agent, not only `map_slot` and `import_suggestions`: `undo`, `revert`, `load_bundle`, `put_blockly` and Optional RM that would touch a leased slot fail with the holder, and the project is left unchanged. Earlier, one agent's Undo could take back another agent's change in a leased slot. `release_slot {all: true}` releases all your leases. Agents get distinct colours in registration order. Two stdio MCP processes from the same IDE are now separate agents (`cursor`, `cursor 2`) even without `register_agent`; before, they shared one identity, so their leases did not keep them apart. The person in the UI is still never blocked.
- **Fix: IDE MCP clients can connect**: the stdio MCP server (`deno task mcp`, `intEHRgrator --mcp`) only read LSP-style `Content-Length` frames, but MCP clients (Cursor, Claude Desktop, VS Code, the MCP SDK) send one JSON message per line, so they never got an `initialize` reply. Both framings are read now, and each reply uses the caller's. A failing tool (for example a slot leased by another agent) is now a tool result with `isError` and the reason, so the agent can react. `intEHRgrator --mcp` no longer opens an empty window for each MCP server an IDE starts, and it exits when the IDE closes the connection.

The "Apply directly / Approve first" select and the "How AI chat maps" credential option are removed (old settings are dropped on load); the Import Suggestions modal is only for pasted answers. A provider that rejects tools gets one suggestions-JSON turn applied directly (revertible). Architecture decision for the next step: chat and MCP will share one write path with one attributed undo step per AI turn ([ADR 0014](docs/adr/0014-one-write-path-attributed-undo.md)).

- Schema-driven toolboxes for JSON / XSD targets ([#19](https://github.com/regionstockholm/intehrgrator/pull/19)).

## [0.3.0] - 2026-08-31

- **Agent API and MCP server** for AI-enabled IDEs ([#17](https://github.com/regionstockholm/intehrgrator/pull/17)).
- Cogwheel mutators replace the optional RM picker ([#10](https://github.com/regionstockholm/intehrgrator/pull/10), [#13](https://github.com/regionstockholm/intehrgrator/pull/13)); undo, search and Spec ticks ([#11](https://github.com/regionstockholm/intehrgrator/pull/11)); RM completeness ([#14](https://github.com/regionstockholm/intehrgrator/pull/14)).

## [0.2.1] - 2026-08-25

- Windows desktop window stays visible; smaller release binaries.

## [0.2.0] - 2026-08-25

- Ships as a Deno desktop workbench instead of an ehrtslib CLI.

## [0.1.0] - 2026-08-25

- First web app and core modules ([#2](https://github.com/regionstockholm/intehrgrator/pull/2)): Click-to-Map ([#4](https://github.com/regionstockholm/intehrgrator/pull/4)), source format handlers ([#5](https://github.com/regionstockholm/intehrgrator/pull/5)), Mapping Spec download / upload ([#7](https://github.com/regionstockholm/intehrgrator/pull/7)), readable TypeScript codegen ([#9](https://github.com/regionstockholm/intehrgrator/pull/9)).
