# Constraint Overlay is RM vs effective OPT, and only when they differ

intEHRgrator scaffolds typed **RM Block**s from a flattened operational template, so the canvas already *is* the specialized model. To illustrate two-level modelling without a second tree, Attribute mouths that the OPT narrowed relative to the RM BMM show a **Constraint Overlay** (Δ, effective interval in overlay colour, RM interval struck through). Unchanged mouths keep today’s single `[min..max]` caption. Prohibited attributes (`max=0`) stay off the canvas but remain in the Optional RM Insertion mutator as non-addable overlay rows — silent disappearance would hide the RM. We do not paint a three-layer RM / archetype / template stack on the mouth: an OPT is already flattened, and the reliable “before” interval is ehrtslib’s RM multiplicity. Archetype-versus-template deltas wait until a differential overlay is available from the clinical-model fileset.
